# Mermapix: Figma Community Publishing Guide

A comprehensive, step-by-step guide for publishing the **Mermapix: Mermaid to Editable Figma** plugin to the Figma Community in full compliance with the [Figma Plugin and Widget Review Guidelines](https://help.figma.com/hc/en-us/articles/360039958914-Plugin-and-widget-review-guidelines).

---

## 1. Plugin Readiness (Pre-Flight Checklist)

- [x] **100% Offline & Zero Network Requests**: `manifest.json` specifies `"networkAccess": { "allowedDomains": ["none"] }`. All runtime dependencies (Mermaid, React, Lucide Icons, the brand icon and the self-hosted Inter / JetBrains Mono woff2 fonts) are bundled into a single standalone file (`plugin/ui.html`). No external scripts, fonts, or CDNs are requested at runtime (verified by loading `plugin/ui.html` with the network disabled: zero requests, both font families loaded). `scripts/build-plugin.mjs` also strips any remote CSS `@import` from the plugin build.
- [x] **Native Auto Layout Engine**: ERD tables become vertical Auto Layout frames; flowchart/sitemap nodes and subgraphs, sequence participants/notes/blocks, class boxes, states, treemap sections and railroad boxes become native frames with the border merged into the frame; every other Mermaid type gets semantic layer names (no "Vector" / "Group").
- [x] **Clean Layers (No Redundant Groups)**: The optimizer dissolves intermediate wrapper groups so users can double-click and edit text immediately without deep drilling.
- [x] **Figma Trademark Compliance**: The listing title is **"Mermapix: Mermaid to Editable Figma"** (brand name "Mermapix" is leading, never prefixed with "Figma"). Logos and iconography are original and do not mimic official Figma brand assets.
- [x] **Visual Assets Prepared**:
  - Icon: `plugin/assets/icon-128.png` (128x128 px PNG, generated by `node scripts/generate-publishing-assets.mjs`)
  - Cover Banner: `plugin/assets/cover-1920x1080.png` (1920x1080 px PNG, same script; committed)
- [x] **Multi-Editor Support**: Ready for both **Figma Design** and **FigJam** (`"editorType": ["figma", "figjam"]`).

## 2. Building & Synchronizing the Plugin

Before publishing or testing the latest changes, compile the production plugin bundle:

```bash
# Build sandbox backend (plugin/src/main.ts -> code.js) and frontend UI (Vite -> plugin/ui.html)
pnpm build:plugin
```

Verify that the following files are present and up to date:
- `plugin/manifest.json`
- `plugin/code.js`
- `plugin/ui.html`
- `plugin/assets/icon-128.png`
- `plugin/assets/cover-1920x1080.png`

---

## 3. Local Testing in Figma Desktop

1. Open the **Figma Desktop** application.
2. Open any design file or create a new blank canvas.
3. Right-click on the canvas or open the top menu:  
   **Plugins** > **Development** > **Import plugin from manifest...**
4. Select the manifest file:  
   `plugin/manifest.json`
5. **Mermapix** will now appear in your *Development Plugins* list.
6. Click **Mermapix** to run.
7. Test core functionality:
   - Select example diagrams from the **Examples** menu (ERD, Flowchart, Sequence, Sitemap).
   - For a full regression pass, run the developer **Mermapix Test Runner** (`plugin-dev/manifest.json`, see `tests/README.md`): it inserts every fixture in light and dark and audits the result.
   - Click **Insert to Canvas**: confirm the diagram is centered in your current Figma viewport.
   - Click an ERD table in Figma: verify in the right-hand properties panel that it is a native **Auto Layout Frame (Vertical)** and field labels can be edited directly with a double-click.
   - Type invalid Mermaid code: the editor shows the error with its line number and **Insert** is disabled (the stale preview is never inserted). **Added!** only appears after the canvas confirms the insert.
   - Switch between **Light / Dark** modes and test **Import Schema (DBML / SQL)**.

## 5. Security & Network Disclosure Questionnaire

Figma reviewers require answers to safety and compliance questions during submission:

| Reviewer Question | Recommended Response | Context & Rationale |
| :--- | :--- | :--- |
| **Does this plugin access external network resources?** | **No** | The plugin configures `"networkAccess": { "allowedDomains": ["none"] }`. All logic and assets are bundled locally into `plugin/ui.html`. |
| **Does this plugin collect or store user data?** | **No** | Zero telemetry, analytics, or user diagram content is stored or transmitted. |
| **Does this plugin use third-party code through `<script src="...">`?** | **No** | All dependencies (Mermaid, React) are bundled statically at compile-time via Vite. |
| **Does this plugin access Figma document content outside the active selection/page?** | **No** | The plugin only creates nodes on the current active page (`documentAccess: "dynamic-page"`). |
| **Is the plugin free or paid?** | **Free** | The plugin is completely free and open source. |

## 6. Review Approval Checklist

1. **Trademark Safety**:
   - The plugin name does not start with "Figma" (e.g., NOT "Figma Mermaid").
   - Descriptions use approved phrasing ("in Figma", "into Figma").
2. **Quality of Execution**:
   - Diagrams are inserted centered within the user's viewport without cluttering the canvas.
   - Text layers remain genuine Figma editable TEXT nodes (Figma's SVG importer creates them from absolutely positioned `<tspan>`s; the plugin restyles them to Inter), not outlined paths.
3. **User-Friendly Error Handling**:
   - Mermaid syntax issues display clear line numbers inside the editor and disable Insert, so no stale or corrupted diagram is inserted. Canvas-side failures show a Figma error notification and the UI never claims success.
4. **Memory Performance**:
   - Configures `documentAccess: "dynamic-page"` to prevent loading entire multi-page documents into memory.

5. **Support & Privacy (required on the listing)**:
   - Support contact: GitHub Issues (`https://github.com/hisyamakbar/Mermapix/issues`) or an email address.
   - Privacy: "Mermapix collects no data. Everything runs locally in Figma; no network requests are made."

---

## 7. Submission & Review Notes

- Submitting requires the **Figma desktop app** and **two-factor authentication** on the publishing account.
- While the plugin waits in the review queue it can still be updated from the publish dialog. Re-run `pnpm build:plugin` first so the uploaded `code.js` / `ui.html` are current, and keep the listing text in sync with what the plugin does.
- Review feedback can be brief and the queue can take days to weeks. Common rejection reasons: crashes or visible developer errors, listing text that does not match behavior, undeclared network access, missing support/privacy information, missing cover/icon.
- After approval, put the Community URL into the web app's "Copy to Figma" guidance (plan item 8.7).
